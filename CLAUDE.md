# kevincole-dev — CLAUDE.md

Personal resume/portfolio site for Kevin Cole. Static site built with Astro + React + Tailwind.

## Dev Commands

```bash
npm run dev      # Start dev server at localhost:4321
npm run build    # Build to ./dist/
npm run preview  # Preview production build
```

## Tech Stack

- **Astro 5** — static site generator, handles routing and page structure
- **React 19** — interactive components (hydrated client-side via `client:load`)
- **TypeScript** — strict typing throughout
- **Tailwind CSS 3** — utility-first styling; all styling is via Tailwind classes (no custom CSS except in `global.css` and config)
- **Shadcn/ui** — component library (new-york style, configured in `components.json`)
- **Lucide React** — icons
- **Basin** (`usebasin.com`) — external service for contact form submissions (no backend needed)

## Project Structure

```
src/
  pages/              # Astro routes
    index.astro       # Main page — uses UrlContext tab management
    with-react-context.astro  # Alt page — uses React Context tab management
    robots.txt.ts     # Dynamic robots.txt
  ui/
    layouts/
      Layout.astro    # HTML shell, persistent background (sandias.jpg)
      MetaConfig.astro # SEO meta tags
      global.css      # Tailwind directives + CSS color variables
    components/       # React components
      Hero.tsx        # Profile photo, name, contact info
      Home.tsx        # Home tab: Hero + Bio
      Work.tsx        # Details tab: Skills + Employment + Education
      Bio.tsx         # Bio text (Desktop/Tablet/Mobile variants)
      ContactButton.tsx / ContactForm.tsx  # Floating contact modal
      button.tsx      # Shadcn button (CVA variants)
      UrlContext/     # Tab state via URL search params (?tab=home|details)
      ReactContext/   # Tab state via React Context API
    blocks/           # Larger composite components
      SkillsTree.tsx  # Recursive hierarchical skills display (folder/file metaphor)
      EmploymentSection.tsx
      EducationSection.tsx
  content/            # Site data (TypeScript arrays/objects)
    skills.ts         # Skill tree hierarchy
    employments.ts    # Employment history
    education.ts      # Education history
  libs/
    utils/index.ts    # cn() (clsx + tailwind-merge), paramToTab()
    enums.ts          # HeaderTabs enum (HOME, DETAILS)
public/               # Static assets: images, logos, favicons
```

## Key Conventions

- **No semicolons**, 2-space indentation (`.prettierrc`)
- **Path aliases**: `@ui` → `src/ui`, `@utils` → `src/libs/utils`, `@hooks` → `src/hooks`
- **Class merging**: always use the `cn()` utility from `@utils` for conditional Tailwind classes
- **Tailwind breakpoints**: custom scale — `sm` (576px), `md` (768px), `lg` (992px), `xl` (1200px), `xxl` (1440px), `xxxl` (1920px)
- **Typography**: `font-sans` = Inter, `font-mono` = JetBrains Mono; custom heading/paragraph sizes defined in tailwind config
- **Animations**: use the custom Tailwind animation classes (`animate-fade-in`, `animate-slide-down`, etc.) defined in tailwind config
- **Icons**: Lucide React only (Folder, File, Home, Briefcase, Mail, ChevronRight, GraduationCap, CheckCircle, X)
- **SVGs**: imported as React components via `vite-plugin-svgr`

## Two Tab Management Patterns

The project intentionally ships **two implementations** of tab state as a showcase:

| Approach | Page | Components |
|---|---|---|
| URL search params (`?tab=home`) | `index.astro` | `UrlContext/` |
| React Context API | `with-react-context.astro` | `ReactContext/` |

Both render the same UI. Prefer the UrlContext approach for new work on `index.astro`; don't collapse the two into one.

## Site Data

To update content, edit the TypeScript files in `src/content/`:
- `skills.ts` — nested `SkillTree[]`, each item has `name`, `type` (folder/file), optional `url` and `icon`
- `employments.ts` — `Employment[]` with company, jobTitle, dates, description, bullets, url, optional image
- `education.ts` — `Education[]` with institution, degrees, url, background, logo

## Environment

- `PUBLIC_SITE_URL` — set in `.env`, used in `astro.config.mjs` for sitemap and meta
- Contact form posts to Basin (external); no backend or API keys needed for local dev

## Build & Optimization

- Assets compressed via `vite-plugin-compression2` (gzip + brotli)
- Sitemap auto-generated by `@astrojs/sitemap`
- Background image uses `background-attachment: fixed` via `.bg-sandias` class
- Images use `content-visibility: auto` for lazy rendering performance
